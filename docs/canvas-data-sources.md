# Canvas browser-session data sources

## Verification status

**Deployment not verified.** The adapter queries below were researched against Instructure's primary `canvas-lms` Ruby GraphQL definitions on `master`, not an authenticated institution's deployed schema. Local tests exercise the real provider, boundary adapters, normalization, pagination and bridge-operation validation against a mocked bridge. They do not prove that BYU–Idaho or another institution exposes these fields, enables introspection, permits session-authenticated API requests, or supports every browser extension feature.

Canvas documents `/api/graphql` as the GraphQL endpoint.[1] The browser owns the authenticated request and its CSRF/session handling. The Node provider never reads cookies, sends a personal access token, performs arbitrary HTTP requests, or accepts a caller-provided GraphQL query. Its operations are fixed read-only `graphql-query`, whitelisted relative `canvas-get`, bounded `canvas-page`, `session-health`, and ID-addressed `download-file` messages.

### Live course-membership finding

A read-only BYU–Idaho check through the authenticated Chromium extension returned **39 self enrollments / 38 unique active, available courses** from `COURSES_QUERY` with `currentOnly: true`, spanning Summer 2024 through Fall 2026. The session-authenticated `GET /api/v1/courses?enrollment_state=active&state[]=available&per_page=100` returned **6 current courses**, matching the actual Canvas dashboard. Thus GraphQL `currentOnly` is not date-effective current-course membership on this deployment; filtering raw active/available workflow states does not remove historical semesters. This is a verified course-discovery observation, not verification of every source in the matrix or a universal dashboard-equivalence guarantee.

The provider uses session GET membership without a bearer token and keeps GraphQL content preferred only inside that scope. Enriched records identify `source: {transport: "graphql", membership: "canvas-get"}`; a current member absent from GraphQL retains its GET record with reason `current_course_membership`. Unsupported/incomplete GraphQL projections retain the complete discovered GET set with the GraphQL-gap reason. Failed membership discovery remains an error so sync can preserve its previous cache.

## Boundary semantics and safety

- **Canvas IDs, not Relay IDs:** `_id` maps to REST-like `id`; GraphQL's global `id` is not persisted as a Canvas entity identity. `ModulePrerequisite.id` is a legacy identifier and is explicitly aliased to `_id` in that query. Large IDs remain strings through the existing `normalize()` boundary.
- **Enum casing follows primary source:** Canvas assignment/submission workflow and submission-type enums use values such as `published`, `graded`, and `online_upload`. Enrollment types use `StudentEnrollment`, `TeacherEnrollment`, etc. The adapter preserves those source values instead of uppercasing or lowercasing every enum.[5][8][17]
- **Effective assignment dates:** `dueAt`, `lockAt`, and `unlockAt` explicitly request `applyOverrides: true`. These are current-user effective dates, not a claim that the full overrides collection has been retrieved. `lockInfo.isLocked` supplies `locked_for_user`; a missing/null lock record falls back rather than inventing an unlocked state.[8][10]
- **Attempts:** GraphQL `allowedAttempts: null` explicitly means unlimited, mapped to the existing REST convention `allowed_attempts: -1`; missing `allowedAttempts` is not confused with null.[8]
- **Rubrics:** Criteria and ratings become the existing `data.rubric` array; rubric metadata becomes `rubric_settings`. No quality score is inferred from criteria text. Unselected association settings/override history and lock-explanation text are not fabricated.
- **Read-only module traversal:** Do not select `Module.progression`. In the inspected primary source its loader calls progression evaluation/persistence methods. Module listing deliberately selects metadata only.[11]
- **Relay pagination:** Every top-level connection uses `first: 100`, opaque `after`, and `pageInfo { hasNextPage endCursor }`. Missing/null connections, nodes or pagination metadata cannot become empty lists. Repeated cursors or more than 10,000 advancing pages fail explicitly. A nested self-submission connection that claims another page causes complete assignment fallback rather than partial flattening.
- **Session GET pagination:** Follow `Link: rel="next"` opaquely, preserving query parameters. Revalidate whitelist, origin, credentials, fragment, endpoint scope and repeated canonical URLs for every page. A non-array collection body is an error. The same 10,000-page ceiling raises an error, never returns truncated data.
- **GraphQL failures:** Any GraphQL errors, including errors accompanying partial `data`, invalidate that projection. Unsupported/missing fields and HTTP 400/403/404/405/422/501 at GraphQL can use the corresponding isolated session GET. Metadata warnings identify kind and reason, never query variables, response messages, URLs, HTML or grades. An unsuccessful fallback remains an error; existing sync can retain stale records.
- **Authentication:** Login HTML, redirects, HTTP 401 and GraphQL `UNAUTHENTICATED` are not interpreted as empty data. They become status 401, retryable guidance: `Open Canvas in your browser and sign in.` A denied GET (403) is not turned into permission to scrape a page.
- **Semantic page fallback:** Only after unsupported session GET (404/405/501), and only with a numeric page/assignment identity, send `canvas-page`. The extension extracts semantic content, not arbitrary selectors from this provider. The result is marked `source: {transport: 'canvas-page', reason: 'session_get_unsupported', complete: false}`. It is not a complete assignment eligibility/rubric record. A slug without a verified numeric page ID does not get guessed into a DOM operation.
- **Provenance:** GraphQL records expose `data.source.transport = 'graphql'`. GET records expose `transport = 'canvas-get'` plus a fixed reason. The adapter supplies REST-like raw records to unchanged domain normalization; no GraphQL types enter academic services.
- **Timeouts:** Every bridge request is bounded by `timeoutMs`; timeout fails explicitly and clears the provider timer. No provider retry loop can hide an expired login or terminal permission failure.
